# MOVI Limitations & Evidence Boundaries

이 문서는 MOVI를 포트폴리오에서 과장 없이 설명하기 위해  
**현재 검증된 범위와 아직 주장하지 않는 범위**를 구분한 기록입니다.

목적은 프로젝트의 약점을 숨기는 것이 아니라,  
면접에서 실제로 설명 가능한 수준을 명확하게 유지하는 것입니다.

---

## 1. Financial Environment

MOVI는 실제 상용 금융 서비스를 운영한 프로젝트가 아닙니다.

### 현재 검증된 범위

- Mock 기반 계좌 / 잔액 / 수취인 / 송금 흐름
- Backend에서 거래 전 검증
- LOW / MEDIUM / HIGH FDS 분기
- idempotency 기반 중복 실행 방어
- 거래 결과 상태 처리
- Frontend–Backend API 통합

### 아직 주장하지 않는 범위

- 실제 은행 계좌를 이용한 상용 송금 운영
- 금융기관 OpenBanking을 이용한 production 운영
- 실제 금융기관 환경에서의 장애 대응
- 실사용자 금융 거래 데이터 기반 운영 성과

포트폴리오에서는 **“금융 서비스 구현”**보다  
**“Mock 금융 환경에서 안전한 거래 흐름과 시스템 통합 구조를 검증했다”**고 표현합니다.

---

## 2. AI Ownership

MOVI에는 Voice AI와 FDS가 포함되어 있지만,  
문하늘이 AI 모델을 개발한 프로젝트는 아닙니다.

### 팀 전체 AI 범위

- STT
- Intent / Entity 추출
- FDS 위험도 평가
- AI 서버

### 문하늘의 검증된 범위

- AI 결과를 서비스에서 어디까지 신뢰할지 정의
- AI와 Backend의 책임 경계 설계
- Voice / FDS API 계약 정리
- AI 응답 이후 Backend 재검증 흐름 설계
- 오류 / timeout / 잘못된 응답 처리 정책
- AI 결과를 포함한 전체 서비스 흐름 통합 검증

따라서 다음 표현은 사용하지 않습니다.

- “STT 모델을 개발했다”
- “FDS 모델을 개발했다”
- “LLM 모델을 설계했다”
- “AI 정확도를 향상시켰다”

대신 다음처럼 설명합니다.

> **AI 모델 자체보다 AI 결과를 실제 금융 기능에 안전하게 연결하기 위한 서비스 구조와 검증 흐름을 설계했습니다.**

---

## 3. AI-assisted Coding

Frontend와 Backend 일부 구현에는  
**Claude / Codex 등 AI 코딩 도구를 많이 활용했습니다.**

따라서 GitHub의 PR 크기, 변경 파일 수, 코드 라인 수를  
개인의 수작업 코딩 능력과 동일하게 해석하지 않습니다.

### 직접 수행한 부분

- 요구사항 정의
- 정상 / 실패 흐름 결정
- API와 상태 전이 기준 정의
- AI 코딩 도구에 구현 요구 전달
- 생성 코드 실행
- 테스트 수행
- 계약 불일치 확인
- 오류 원인 확인
- 실제 요구사항과 맞지 않는 동작 수정
- 문서와 구현 비교

포트폴리오에서는 이를 다음처럼 표현합니다.

> **AI 코딩 도구를 활용해 구현하고, 요구사항과 실제 동작이 일치하는지 반복 검증했습니다.**

“직접 모든 코드를 작성했다”는 표현은 사용하지 않습니다.

---

## 4. Accessibility Validation

MOVI는 시각 중심 UI 이용에 어려움이 있는 사용자를 주요 대상으로 설계했지만,  
현재 접근성 검증에는 아직 빈칸이 있습니다.

### 설계 / 코드 수준에서 고려한 내용

- 음성 기능에 키보드·터치 대안 유지
- 음성만으로 거래 확정 금지
- 결과를 화면 텍스트와 음성으로 함께 제공
- 오류 후 재시도 / 대체 흐름 고려
- 일부 focus 이동과 접근성 마크업 보완

### 현재까지 수행한 수동 검증

- Keyboard-only: 로그인 일부 흐름, 잔액조회 핵심 흐름, 송금 수취인 선택
- 200% 확대: Login / Accounts / Balance / Transfer / Review / Result 핵심 화면

### 아직 완료되지 않은 검증

- 실제 시각장애 사용자 usability test
- VoiceOver 기반 전체 핵심 흐름 검증
- TalkBack 기반 전체 핵심 흐름 검증
- 실제 모바일 기기 reflow 점검
- screen reader 기반 송금 완료 E2E 검증

따라서 현재는 다음 표현을 사용하지 않습니다.

- “시각장애 사용자 접근성을 검증했다”
- “접근성 기준을 충족했다”
- “VoiceOver / TalkBack 테스트를 완료했다”

수동 검증 결과와 이후 발견되는 문제·수정 내역은 [validation.md](./validation.md)에 기록합니다.

---

## 5. User Validation

현재 MOVI에는 실제 타깃 사용자 대상 정식 사용성 테스트 결과가 없습니다.

따라서 다음 항목은 아직 증거가 없습니다.

- 사용 편의성 향상 수치
- 송금 성공률 향상
- 오류율 감소
- 사용 시간 단축
- 만족도
- 실제 사용자 선호
- 시각장애 사용자 대상 정성 인터뷰 결과

사용자 성과를 보여주기 위해 임의의 숫자를 만들거나  
팀 내부 테스트를 외부 사용자 성과처럼 표현하지 않습니다.

---

## 6. FDS Evaluation

MOVI의 FDS는 서비스 흐름에서 위험도를 LOW / MEDIUM / HIGH로 분기하는 역할을 하지만,  
문하늘의 개인 프로젝트 성과로 다음을 주장하지 않습니다.

- FDS 모델 정확도
- 탐지율 / 재현율
- 오탐률 개선
- 이상거래 탐지 성능 향상
- ML 모델 튜닝 성과

문하늘이 설명할 수 있는 범위는 다음입니다.

- Backend가 FDS에 제공할 사실 데이터와 책임 경계
- 위험도에 따른 서비스 정책
- FDS 실패 시 fail-closed 처리
- 보호자 알림이 필요한 조건
- FDS 결과를 금융 실행 전에 Backend에서 해석하는 흐름

---

## 7. Production / Scale

MOVI는 실제 대규모 운영 시스템이 아닙니다.

다음과 같은 표현은 현재 근거가 없습니다.

- 대용량 트래픽 처리
- 고가용성 운영
- 무중단 배포
- 대규모 사용자 동시 접속
- 실서비스 장애 복구
- 성능 최적화 수치
- 응답속도 개선 수치
- 실제 운영 SLA

테스트와 Mock 기반 검증 결과를  
production 운영 성과로 확대해서 설명하지 않습니다.

---

## 8. Team Result vs. Personal Contribution

MOVI의 기능 전체를 문하늘 개인 결과로 표현하지 않습니다.

예를 들어 다음은 **팀 전체 결과**입니다.

- 전체 Frontend
- 전체 Backend
- AI 서버
- STT
- FDS
- 인증 전체 기능
- 계좌 / 거래내역 전체 기능
- 보호자 알림 전체 기능

문하늘의 개인 기여는 [contribution.md](./contribution.md)에 정리한 범위만 사용합니다.

---

## 9. Evidence Levels

포트폴리오에서 MOVI 관련 정보는 다음 기준으로 구분합니다.

### A. GitHub / 문서로 검증된 사실

- Frontend–Backend–AI 통합 명세
- Voice / FDS 계약
- 음성 이체 Backend 흐름
- Frontend–Backend 계약 audit
- 직접 입력 송금 통합
- idempotency 및 실패 흐름

### B. 본인 확인이 필요한 사실

- 문제 정의 과정의 세부 배경
- 역할 분담 과정의 세부 맥락
- 실제 팀 내 의사결정 과정
- 특정 기능을 선택한 이유 중 문서에 남지 않은 부분

### C. 현재 증거가 없어 사용하지 않는 주장

- 실제 금융망 운영
- 실제 시각장애 사용자 검증 완료
- AI 모델 개발
- FDS 성능 향상
- 대규모 트래픽 운영
- 사용자 성과 수치

---

## 10. Interview-safe Boundary

현재 MOVI를 면접에서 설명할 때 가장 안전한 범위는 다음입니다.

> **MOVI는 시각 중심 금융 UI 사용이 어려운 사용자를 고려한 음성 금융 서비스 팀 프로젝트입니다. 저는 AI 모델 자체를 만들지는 않았고, 음성 AI가 해석한 결과를 실제 금융 실행에 바로 사용하지 않도록 Frontend–Backend–AI의 책임과 검증 흐름을 설계했습니다. 누락 정보 재질문, 명시적 거래 확인, FDS 실패 시 거래 중단, idempotency 같은 흐름을 AI 코딩 도구를 활용해 구현·검증했습니다. 실제 금융망이나 실제 시각장애 사용자 운영 경험으로 확대해서 설명하지 않습니다.**

이 범위보다 강한 표현을 사용하려면 추가 증거가 필요합니다.
